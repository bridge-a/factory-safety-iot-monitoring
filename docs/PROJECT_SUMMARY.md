# 项目阶段总结与课程设计报告写作依据

项目：面向工厂的安全生产物联网监控网络  
课程：物联网系统综合课程设计  
整理日期：2026-10-15

## 1. 当前结论

已搭建面向小型工厂模拟场景的物联网监控原型，完成环境数据采集、局域网传输、实时监控、历史存储、分级告警、声光联动、QQ 邮件通知，并增加明火视觉检测。用户确认主要联调流程及关闭网页后的后台告警正常，可以进入课程设计报告整理阶段。

本总结依据任务书原文、当前代码、用户提供的串口/部署日志、网页截图和逐项联调反馈。课程报告按实际实现和现有证据撰写；教师现场验收另按课程安排进行。

## 2. 系统组成

| 层次 | 器件或软件 | 实际作用 |
| --- | --- | --- |
| 采集与执行 | ESP32-S3 | 传感器读取、有效性判断、MQTT 上报、本地告警及平台声光指令执行 |
| 温湿度 | SHT31 | 温度和相对湿度采集 |
| 气体 | Sensirion SCD41 | CO₂ 采集，作为气体异常的替代演示 |
| 烟雾 | MQ-2 | 模拟电压经分压接入 ADC，以相对读数参与阈值判断 |
| 辅助环境量 | BH1750 | 光照采集，供环境观察与辅助展示 |
| 现场报警 | LED、有源蜂鸣器 TMB12A05 | 依据本地和平台告警等级响应 |
| 视觉采集 | USB 摄像头 | 现场画面和火焰检测输入，沿用用户确认的 180° 转正 |
| 边缘主机 | Raspberry Pi 5 Model B，8GB | 运行 Mosquitto、Flask 后台、SQLite、视觉推理与邮件队列 |
| 通信与交互 | Wi-Fi、MQTT、浏览器、QQ SMTP | 实现采集上报、控制下发、页面查询和远程通知 |

当前固件对应 I²C SDA/SCL 为 GPIO8/GPIO9；MQ-2 AO 经分压接 GPIO4；LED 使用 GPIO5，蜂鸣器使用 GPIO6。最终报告接线图以装置实物和整合固件共同核对，说明蜂鸣器驱动电路与负载电流的设计取舍，不将开关成功等同于电气可靠性测量。

## 3. 已完成的软件功能

| 页面或模块 | 功能 |
| --- | --- |
| 监控总览 | 实时环境仪表、摄像头画面、明火标框、综合风险、最新事件与联动状态 |
| 历史趋势 | 时间范围/模式/指标查询、趋势图、采样明细、统计与 CSV 导出 |
| 告警记录 | 等级和类别筛选、分页、事件快照、邮件状态与视觉截图详情 |
| 明火检测 | 检测运行状态、置信度、实际检测帧率、火焰框及近期明火事件 |
| 设备管理 | 节点在线、数据来源、器件状态、MQTT 主题和邮件队列信息 |
| 模拟与联调 | 全模拟、混合和真实采集模式，烟雾场景注入与联动反馈 |
| 后台处理 | 周期采样、无效值/过期值处理、独立告警状态、事件去重、持续恢复和邮件重试 |

SQLite 分别存储环境采样和告警事件。后台承担检测与通知工作，网页负责展示和交互；关闭网页不会停止树莓派上的监测服务。用户已确认关闭网页后的告警测试正常。

## 4. 两类异常如何形成联动

环境异常由各指标阈值独立判断。ESP32 具备本地规则，树莓派后台也会判断和记录事件，再通过 MQTT 下发平台告警等级。固件输出采用本地与平台的较高等级。

明火检测共享已有摄像头的最新画面，使用第三方预训练 YOLOv8n 模型和 ONNX Runtime CPU 推理。只使用 fire 类触发视觉报警，烟雾仍由 MQ-2 独立判断。默认输入 320×320、目标检测频率 2 FPS、置信度阈值 0.55；连续至少 1.5 秒且至少 3 个不同帧检出后报警。

确认异常后，平台记录事件、更新综合风险、弹出网页通知、进入 QQ 邮件发送队列，并联动 ESP32 声光设备。持续同类异常合并，恢复须保持连续有效正常数据 15 秒；缺测与摄像头中断不作为恢复证据。明火报警另保存对应的标框截图。

| 视觉联动 | 摄像头拍摄手机火焰视频，截图显示标框及约 84%～86% 置信度；用户确认事件、弹窗、实体声光、邮件、截图与无火恢复正常 |
| 关闭网页 | 用户在关闭网页后台告警检查后确认验证成功；保持树莓派后台程序运行 |

66 ms 是合成帧处理耗时，不是端到端告警延迟。84%～86% 是示例帧的检测置信度，不是准确率、召回率或 mAP。现有记录未提供量化丢包率、持续运行时长、误报率与传感器标定结果，报告不补写虚构数值。

## 6. 报告中的实现边界

- 气体异常采用 CO₂ 替代演示，写明替代目的和测试条件，不将其写成对具体有毒气体的实测。
- MQ-2 已接入 ADC 和告警流程，以烟雾相对值表示；未完成浓度标定时，不换算成烟雾 ppm。
- 视觉测试证据来自火焰视频回放；真实小火焰、玻璃反射和暖色物体的系统测试应独立记录。
- 模型采用第三方预训练权重。项目贡献在选型部署、预处理和后处理、连续确认、截图与多通道告警集成，不描述为自行训练或改进网络结构。
- 原文物项目保留在独立目录。本项目复用既有技术经验、传感器和部分界面构思，新增工厂场景中的 MQ-2、声光控制、邮件、明火检测及相应联调。
- 任务书的工业环境适应性、传感器布局与准确性要求，在报告中分别说明采取的措施、已有实验和改进空间；功能联调结果不代替这些量化实验。

## 7. 课程报告的内容安排

1. 设计任务与需求分析：任务书目标、模拟场景、功能要求及替代方案。
2. 系统总体设计：分层架构、硬件选型、通信关系、数据与控制流程。
3. 硬件设计：传感器接口、供电和分压、声光连接、摄像头及装置布局。

5. 异常报警与明火检测：分级阈值、去重/恢复、QQ 邮件、模型推理和截图联动。
6. 系统调试与测试：测试条件、步骤、预期与实际结果、截图和性能记录，明确回放与实景。
7. 总结与改进：完成情况、设计取舍、局限和可继续完善的方向。
