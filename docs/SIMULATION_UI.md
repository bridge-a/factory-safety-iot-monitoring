# 模拟与联调页改版

日期：2026-10-13。属于 `main` 开发版，本轮视觉效果待确认；最近发布标签仍为 v0.1.0。

## 页面组织

页面沿用告警、历史、明火与设备页的导航和顶栏。原先的多层标题、六张独立场景卡片和大块深绿读数面板，改成模式设置、场景列表与反馈侧栏。

![模拟联调页：六个测试场景与实时读数](images/simulation.png)

截图使用模拟数据；邮件未启用，实体声光尚未联调。

- 上方保留三种运行模式，说明切换作用于整个后台，显示各模式的数据来源。
- 六个烟雾场景按行排列，整行可操作，当前场景有浅绿底色、左侧标记与文字确认。保留正常、逐渐升高、预警、报警、恢复和断线行为。
- 右侧集中烟雾相对值、来源、状态、阈值和网页／邮件／声光状态，并提供告警与历史入口。
- 去重、15 秒恢复确认、断线判定和实机验证说明放入可展开的“联调检查要点”。
- 1366 × 768 下主要操作与反馈位于首屏；小屏使用纵向布局，辅助文字至少 12px。

设计参考：[shadcn-admin 设置页](https://shadcn-admin.netlify.app/settings)、[IBM Carbon Structured list](https://www.carbondesignsystem.com/building-blocks/core/components/structured-list/guidelines)。参考其表单层次、分隔线、行式选项与状态区分，没有复制组件代码或第三方素材。

## 操作反馈

场景点击后立即提交，应用期间禁用重复操作。成功后显示后台确认的模式与场景；失败时显示原因并重新获取状态，避免把未应用的选择留在页面上。较早的状态响应不会覆盖之后成功应用的场景。

真实采集模式禁用所有模拟场景。后台断线时清空实时读数、取消当前场景标记并禁用控制；连接恢复或手动刷新成功后恢复操作。通知接口单独失败时，弹窗状态显示异常，采样读数仍可用。

邮件启用与允许模拟邮件分别显示；页面不把“已启用”作为实际邮件到达的证据。烟雾数值的正常状态是当前采样判定，事件恢复仍由后台持续确认，不能以按钮选中或数值变绿代替恢复事件。

专项检查使用隔离数据库与响应夹具，不启动外部 MQTT 或 SMTP；全站回归使用独立模拟后台。覆盖五种宽度、键盘操作、三种模式、六种场景、失败和离线恢复、通知配置及响应顺序。截图与报告保存到忽略的 `artifacts/simulation-check/`。

本轮没有修改传感器采集、报警阈值、恢复规则或邮件发送后端。界面整理不代表树莓派部署、真实邮件、MQ-2 和声光动作已验收。后续主线仍按 [开发计划](../DEVELOPMENT_PLAN.md) 完成真实联调。
