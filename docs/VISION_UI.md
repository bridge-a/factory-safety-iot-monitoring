# 明火检测页改版

日期：2026-10-12。属于 `main` 开发版，本轮视觉效果待确认；最近发布标签仍为 v0.1.0。

## 页面组织

旧页面的全局状态栏、重复标题、接入进度和截图占位卡片使现场画面位置偏低。本轮沿用告警页与历史页的导航、风险顶栏和配色，页面保留一个主标题，按现场画面、检测状态、明火事件组织内容。

![明火检测页：摄像头与模型尚未接入](images/vision.png)

- 左侧 16:9 画面区使用深灰绿色，移除工厂装饰插画及背景网格，让后续现场图像成为重点。
- 右侧集中显示摄像头、模型和待测的帧率、置信度；未运行检测时明确说明无法判断明火状态。
- 取消页面里的开发接入步骤；实施安排继续保存在 [开发计划](../DEVELOPMENT_PLAN.md)。
- 下方通过 `source=vision` 读取全部模式中的最近四条视觉事件，标明来源和模式，链接到已应用明火筛选的告警页。
- 暂无记录、读取失败和初次加载分开展示；状态请求失败后显示未知，刷新后可恢复。
- 手机端把状态区移到画面下方；窄屏继续转为单列，保留完整文字导航。

参考了 [Frigate 官方 Live View 文档](https://docs.frigate.video/usage/live/)、[公开演示](https://demo.frigate.video/) 的单摄像头布局与事件组织；简洁导航继续沿用此前参考 [shadcn-admin](https://github.com/satnaing/shadcn-admin) 的项目风格。本轮没有复制第三方代码或监控画面。

## 实现边界

这是界面与已有接口的整理。当前后台视觉状态仍为 `pending`，没有视频流、明火推理或截图保存功能，也不会生成真实明火事件。记录列表可以读取现有事件存储中的视觉类型数据；验证记录来自隔离的模拟夹具。

摄像头、模型接入后，还需连接真实视频流、检测状态和推理指标，并完成事件持续确认、截图保存与通知联动。FPS 和置信度当前保持空值，不使用模拟数字制造已接入的效果。明火不等同于吸烟行为或故障原因，烟雾检测与视觉检测独立判断。

## 验证方式

```powershell
.\.venv\Scripts\python.exe tests/vision_ui_check.py
```

脚本使用隔离数据库，关闭外部邮件。截图与结果保存在不上传的 `artifacts/vision-check/`，包含：

- 1920、1366、768、390、320 像素宽度无整页横向溢出；笔记本首屏显示完整画面区。
- 初次无连接、断线恢复、刷新以及事件读取失败的处理。
- 六条视觉夹具只展示最新四条；烟雾记录不混入，模拟来源保持可见。
- 事件内容作为纯文本呈现，没有截图时不伪造缩略图。
- “全部记录”正确进入告警页的明火筛选结果。

全站回归结果见 [验证记录](VALIDATION.md)。下一页为设备管理，本轮未进行实机或模型验收。
