# 设备管理页改版

日期：2026-10-12。属于 `main` 开发版，本轮视觉效果待确认；最近发布标签仍为 v0.1.0。

## 页面组织

原页面的大块绿色节点横幅、重复标题和多个独立卡片占据了较多空间。本轮沿用告警、历史与明火页的共用导航和顶栏，把设备管理整理成节点摘要、器件清单、通信与邮件状态三部分。

![设备管理页：模拟读数与未接入的实际设备](images/devices.png)

截图为浏览器窗口截图，显示的是模拟数据。节点未接入、邮件未启用和读数来源均按对应状态展示。

- 顶部摘要保留 ESP32-S3 型号、实际连接、设备标识与最近实际上报时间，取消大面积深绿色横幅。
- 清单包含四项传感器配置、摄像头和声光执行器；“6 项配置”不是已连接的实物数量。
- SHT31 只占一行，温度和湿度分别保留数值、单位与来源；单项缺失不会清除另一项有效读数。
- 缺失值显示为空，模拟数据不会将实际设备标记为在线；MQTT 代理连接与采集节点在线分别呈现。
- 右侧通信区显示订阅主题和连接信息；邮件区分开展示等待投递、发送中、已提交和失败计数。
- 数据自动更新，顶部保留手动刷新。后台断开后清空实时读数，保留静态设备配置；队列读取失败单独提示，旧响应不会覆盖更新的结果。
- 手机上表格保留可横向滚动区域，通信与邮件区移到清单下方；桌面继续使用固定侧栏。

### 评审后的细节调整

- 模拟来源用黄褐色，实际采集用绿色，待接入、待联调和无有效数据用灰色；保留逐项来源，便于后续混合联调。
- 设备页辅助文字至少 12px，提升说明、单位与邮件队列标签的对比度；模拟说明改为“模拟读数仅用于功能演示与联调，不代表硬件已连接。”
- 订阅主题右侧支持点击或键盘复制，成功显示“已复制”，失败时选中主题并提示手动复制；缺少主题或后台断线时禁用按钮。
- 原有页面结构、底部留白以及共用顶栏保持不变。

复制优先使用 [Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)。普通 HTTP 环境下尝试选区复制；该兼容路径使用的 [execCommand](https://developer.mozilla.org/en-US/docs/Web/API/Document/execCommand) 已弃用，不保证所有浏览器支持，因此保留明确的手动复制提示。

设计参考：[shadcn-admin 用户列表](https://shadcn-admin.netlify.app/users)、[ThingsBoard 设备文档](https://thingsboard.io/docs/user-guide/devices/)。取用其信息组织与列表布局思路，实现仍为原生 HTML / CSS / JavaScript，没有复制第三方代码或示例数据。

## 验证与边界

```powershell
.\.venv\Scripts\python.exe tests/devices_ui_check.py
```

独立检查使用临时数据库和明确的响应夹具，不启动实际 MQTT 连接，不发送外部邮件。结果与截图写入忽略的 `artifacts/devices-check/`，覆盖：

- 1920、1366、768、390、320 像素宽度无整页横向溢出，1366 × 768 下清单完整显示于首屏。
- 模拟读数与设备在线分开显示；混合模式、SHT31 部分缺失和过期读数显示正确。
- MQTT 已连接但节点离线时，两个状态分别呈现。
- 邮件配置错误、队列失败、后台断线与刷新恢复。
- 并发刷新时，较早的队列结果不会覆盖新的结果；页面入口链接有效。
